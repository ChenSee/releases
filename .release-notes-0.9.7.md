# TrueAsync PHP 0.9.7 (php 8.6)

The fork moves forward to upstream PHP `master` as of 2026-08-24 — 204 commits —
and the HTTP server renames its response body API. Both are in this release, so
adapters written against `send()` and `isClosed()` need a line each.

## Highlights

- **Upstream merged, and one thing it changed had to be followed.** PHP now
  passes `$this` as a `zend_object*` and stores it as one in `zend_closure`.
  `ext/async` kept a copy of that layout, so every `$this`-bound closure sent to
  a worker thread crashed on its first property fetch — 37 tests across
  `thread`, `thread_channel` and `thread_pool`. Fixed in php-async v0.9.5, and a
  build that carries the merge without it is not usable.
- **A write can report its own failure.** ABI 0.26.0 adds
  `ZEND_ASYNC_IO_WRITE_FAILED` on the io handle. Before it a fire-and-forget
  write had no verdict to give, so a peer that had gone looked exactly like one
  that had merely finished sending — a half-closed client lost the rest of its
  response, 110 bytes of 4 MiB over HTTP/1.
- **The response body API is renamed.** `write()` streams and puts bytes on the
  wire at the first call; the buffered append is `appendBody()`; `isClosed()` is
  `isEnded()`; `sendable()` is gone, replaced by `isWritable()` and `tryWrite()`.
- **A `$response` kept past its request no longer crashes the worker.** It held
  the transport's per-request state, which is freed when the request finalizes.

## Components (php-src trueasync-0.9.7, php-async v0.9.5, server v0.13.0)

**ABI 0.26.0** — `ZEND_ASYNC_IO_WRITE_FAILED`.

### Added
- **server: a streamed body can be framed by a declared `Content-Length`** on
  every protocol, and the body is held to that number.
- **server: `tryWrite()`, `awaitWritable()`, `trySseEvent()`, `tryWriteMessage()`**
  — offer a chunk without waiting, or wait out a refusal.
- **server: `abort()`** ends a started stream as failed: HTTP/1 withholds the
  terminator, HTTP/2 and HTTP/3 reset the stream.
- **server: rooms build without WebSocket.**

### Fixed
- **server: a half-closed peer lost the rest of its response** (110 bytes of
  4 MiB over HTTP/1; no END_STREAM over HTTP/2).
- **server: pipelined HTTP/1 responses came back out of order** when a large one
  followed a small one.
- **server: a large HTTP/2 response was truncated** for a client that refills its
  window often — 2686976 bytes of 3 MiB.
- **server: HTTP/2 and HTTP/3 sent no `Content-Length`,** `HEAD` and static files
  included.
- **server: HTTP/3 dropped a streamed response's trailers on `end()`** and
  stopped emitting response headers at 256.
- **server: a bailed-out handler answered 200 over its half-built body.**
- **server: `StaticHandler` refused the prefix `/`,** which is the document root
  a framework runner mounts.
- **php-async: no PHP object is built after the object store is gone** — a write
  cancelled at reactor shutdown took the process with it.
- **php-async: a write is not truncated when it overflows the writev slot table.**

### Performance
- **server: a buffered HTTP/2 or HTTP/3 response states its `Content-Length`
  without the header table** — 95 ns per response, 3.6% of a 3-byte one, paired
  over 19 rounds.
- **server: a streamed HTTP/1 chunk goes out as one write below 32 KiB** — +81%
  at 4 KiB chunks.

### Changed
- **server: `setStatusCode()` takes 200 to 599** and refuses an interim status.
- **server: `RoomDeliveryException` extends `HttpServerException`.**
